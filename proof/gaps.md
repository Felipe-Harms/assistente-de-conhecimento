# REQ-005 Documented Gaps

This file is **canonical** (tracked in git) and lists the known gaps and
out-of-scope decisions for the demo acceptance proof under
`data/corpus/`. The companion artifact `results.md` (generated by
`scripts/run_proof.py`) records the live per-question status; this file
documents the editorial / scope decisions that produced the question
set in `questions.json`.

## What the demo corpus is

The demo corpus ships seven short, openly licensed documents covering
household topics (cat care, dog adoption, indoor herbs, home
fermentation), a fictional Python tool (uvtool), a primer on open
source licenses, and a home fitness routine PDF. The intent is to
exercise the full REQ-005 pipeline — ingest → retrieval → cited answer
→ refusal — without depending on any vendor credentials or external
network calls (the embedding client is the deterministic local stub
controlled by `EMBEDDING_STUB=true`).

## What the demo corpus is not

The following areas are **intentionally absent** from the corpus and
therefore fall outside the scope of the acceptance proof:

- **Currency / live financial data.** The corpus has no price feeds,
  market quotes, or time-sensitive economic numbers.
- **Cloud-native orchestration.** Kubernetes, Helm, Terraform, and
  other platform topics are out of scope; questions about them must
  refuse (see Q10).
- **World geography / trivia.** Capitals, populations, and similar
  reference questions are not in scope (Q11).
- **Sports, politics, and other time-sensitive events.** The corpus
  does not pretend to be authoritative on current events (Q12).
- **Live model integration.** `EMBEDDING_STUB=true` is the default
  configuration; switching to `EMBEDDING_STUB=false` requires an
  external API key the operator must supply via `.env` — the
  acceptance proof does not exercise that path.

## Known limitations of the acceptance proof

1. **Deterministic embeddings.** With `EMBEDDING_STUB=true`, similarity
   scores are stable across runs, but the absolute scores are not
   comparable to production-grade embedding models. The
   `RETRIEVAL_MIN_SCORE` threshold (default `0.20`) is calibrated for
   the stub, not for OpenAI or other vendor embeddings.
2. **Single-workspace scope.** The proof runner uses the `default`
   workspace and a single `proof-corpus` collection. Multi-workspace
   isolation (P1 product work) is out of scope here.
3. **Acceptance drift tolerance.** `verify-proof-artifacts.sh` allows
   up to 20% of questions to drift between expected and actual status.
   A clean run should show zero drift; the tolerance exists to absorb
   minor model / chunker changes during iteration.
4. **questions.json is a fixture.** It is committed to the repo so a
   fresh clone has a reproducible acceptance set. Editing it without
   re-running `scripts/run-proof.sh` will leave `results.json` out of
   sync with the questions.

## Out of REQ-005 scope

This file does not list product P1 gaps (advanced workspaces,
retention policies, analytics dashboards). Those are tracked
separately and are deliberately not part of the REQ-005 acceptance
contract.
