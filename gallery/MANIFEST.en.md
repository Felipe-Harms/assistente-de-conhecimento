This manifest is the canonical inventory of the review-ready gallery.
Every PNG file referenced here is checked by `scripts/verify-gallery.sh`
for presence, valid PNG header, sane dimensions and non-zero size.

## Required states

The demo proves the four explicit UI states the buyer can audit:

- **idle** — UI loaded with the brand surface, no question submitted.
- **answered** — on-topic question, citations rendered with file + score + snippet.
- **refused** — off-topic question, `insufficient_evidence` banner with `reason` and `best_score` / `threshold`.
- **auth-error** — UI surfaces a 401 (simulated via Playwright `page.route()` interception; the live API is intentionally `AUTH_ENABLED=false` for the demo).

The shipped corpus is small and synthetic; the on-topic question
("vaccinations for an adopted dog") is reproducible. Re-running
`scripts/run-demo.sh` produces byte-different but visually identical
screenshots because the UI does not embed a clock or random seed.

## Provenance

The screenshots are produced inside the running test container, which
runs the Playwright Python client against Chromium 1148. The UI is
loaded at `http://ui:80?workspace=<gallery-uuid>` so each capture is
isolated. No real customer data, no third-party branding and no
embedded credentials are present in any PNG; the screenshots are
empty UI surface on the local stub.

The same PNGs can be regenerated by running:

```bash
./scripts/run-demo.sh        # capture
./scripts/verify-gallery.sh   # validate against this manifest
```

`scripts/verify-gallery.sh` exits non-zero if:

- A PNG listed here is missing.
- A PNG has a corrupted or non-PNG header.
- Dimensions fall outside the 800×600 / 4096×4096 sanity range.
- The manifest does not reference all four states.
- Any secret-shaped content appears in `scripts/_demo_*.py` or
  `scripts/run-demo.sh` (defensive sweep; the gallery itself cannot
  carry secrets by construction).

## Known UI size variation

The `02-answered.png` screenshot is taller (1868 px) because the
citations card renders below the answer and the page is captured in
`full_page=True` mode. The other three states fit in the viewport
(~878 px). This is the expected behaviour of the static UI and not a
regression.

## Limitations disclosed in the copy

- **No real customer data.** The corpus is synthetic / openly licensed
  (cat care, dog adoption, fermentation, fitness, herb garden,
  open-source licensing, a fictional Python tool). Buyers cannot use
  these PNGs as evidence of any real deployment.
- **Stub embeddings.** All four states are produced against the
  deterministic local stub. Switching to a vendor embedding will
  change the cosine scores and may shift a borderline answer into
  `refused` (the documented Q13 drift is the canonical exposure).
- **Auth-error is simulated.** The shipped `.env` ships with
  `AUTH_ENABLED=false` so the live stack is intentionally permissive.
  The 401 state is captured via Playwright `page.route()`, not by
  flipping the API's auth flag. The auth gate itself is exercised
  end-to-end by `tests/e2e/test_ui_auth_gate.py`.
